# 选择性持久化与同步机制（db_sd_list）

## 概述

通过 `db_sd_list` 配置项实现数据库级别的选择性 RDB/AOF 持久化和主从复制控制。

在 Redis 多数据库场景下，该机制允许用户精确控制哪些数据库需要持久化到磁盘或同步到从节点，从而：
- 降低磁盘 I/O 和网络带宽消耗
- 支持多租户场景下的差异化数据保护策略
- 允许临时数据或缓存数据不参与持久化

## 配置方式

### redis.conf 配置
```conf
# 仅对 db0, db2, db5 进行持久化和同步
db_sd_list "0,2,5"

# 空配置表示允许所有数据库（默认行为，向后兼容）
# db_sd_list ""
```

### 运行时配置
```
CONFIG SET db_sd_list "0,1,3"
CONFIG GET db_sd_list
CONFIG REWRITE  # 支持持久化配置
```

## 实现原理

### 数据结构
```c
// server.h
char *db_sd_list_str;         // 配置字符串，如 "0,2,5"
unsigned long *db_sd_bitmap;  // 位图用于快速查找
size_t db_sd_bitmap_size;     // 位图大小（字节）
```

### 位图设计
- 使用位图（bitmap）实现 O(1) 时间复杂度查询
- 每个 bit 代表一个数据库 ID
- 位图为 NULL 或空表示允许所有数据库（向后兼容）

### 检查流程
```
┌─────────────────────────────────────┐
│  RDB/AOF/复制操作触发               │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│  dbIndexInSdList(dbid) 检查         │
│  - 位图为 NULL → 允许              │
│  - 位图存在 → 检查对应 bit         │
└──────────────┬──────────────────────┘
               │
       ┌───────┴───────┐
       │               │
       ▼               ▼
   允许 (1)        拒绝 (0)
       │               │
       ▼               ▼
  执行操作       跳过该数据库
```

## 核心函数

### dbIndexInSdList(int dbid)
检查数据库 ID 是否在允许列表中。

**位置：** `src/db_sd_list.c:19`

**返回值：**
- `1` - 数据库在列表中，允许同步/持久化
- `0` - 数据库不在列表中，拒绝同步/持久化
- `1` - 位图为空或 NULL，允许所有数据库（向后兼容）

### applyDbSdList(const char **err)
应用 `db_sd_list` 配置，解析字符串并构建位图。

**位置：** `src/config.c:2676`

**处理流程：**
1. 释放旧的位图
2. 空字符串处理（允许所有数据库）
3. 解析逗号分隔的整数列表
4. 构建位图

### freeDbSdList(void)
释放 `db_sd_list` 配置占用的内存。

**位置：** `src/db_sd_list.c:35`

## 集成点

### 1. RDB 持久化 (`src/rdb.c`)
```c
/* Check if this database should be saved (db_sd_list filtering) */
if (!dbIndexInSdList(dbid)) {
    continue;  // 跳过该数据库
}
```

### 2. AOF 持久化 (`src/aof.c`)
```c
/* Check if this database should be persisted (db_sd_list filtering) */
if (dictid >= 0 && !dbIndexInSdList(dictid)) {
    continue;  // 跳过该数据库
}
```

### 3. 主从复制 (`src/server.c`)
```c
/* Check if this database should be synced (db_sd_list filtering) */
if (dbid >= 0 && !dbIndexInSdList(dbid))
    return;  // 不向从节点发送该数据库的变更
```

## 使用场景

### 场景 1：多租户数据隔离
```conf
# 租户 A（付费用户）- 需要持久化
db_sd_list "0,1"

# 租户 B（免费用户）- 仅内存缓存
# 数据库 2-15 不参与持久化，节省存储成本
```

### 场景 2：热冷数据分离
```conf
# 热数据（频繁访问）- db0 参与持久化和复制
# 冷数据（归档数据）- 其他数据库可选
db_sd_list "0"
```

### 场景 3：临时数据处理
```conf
# 会话数据、临时缓存不持久化
# 仅持久化核心业务数据
db_sd_list "0,1,2"  # 核心业务库
# db3-db15 用于临时数据，重启后自动清空
```

### 场景 4：降低从节点负载
```conf
# 主节点：16 个数据库
# 从节点：仅同步关键数据库，减少网络带宽
db_sd_list "0,2,4,6"
```

## 边界处理

| 输入 | 处理方式 |
|------|----------|
| 空字符串 `""` | 允许所有数据库 |
| NULL | 允许所有数据库 |
| 负数 | 忽略 |
| 超出范围的 ID（>= dbnum） | 忽略 |
| 非数字 | 忽略（atoi 返回 0） |
| 重复 ID | 位图自动去重 |
| 空格 | 自动忽略（atoi 处理） |

## 注意事项

1. **配置变更时机**：建议在服务器启动前配置，运行时修改可能影响正在进行的持久化操作

2. **数据库数量依赖**：位图大小基于 `server.dbnum`，修改 `databases` 配置后需重新设置 `db_sd_list`

3. **向后兼容**：未配置时默认允许所有数据库，保持与旧版本兼容

4. **内存占用**：位图内存占用极小（16 个数据库仅需 2 字节）
