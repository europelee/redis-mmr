# 持久化机制

Redis 提供两种持久化方式：RDB 快照和 AOF 日志。本章详细描述两种机制的原理、格式和使用策略。

## 持久化方式总览

```
┌─────────────────────────────────────────────────────────────┐
│                    Redis 持久化机制                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  RDB (Redis Database)              AOF (Append Only File)  │
│  ────────────────────              ───────────────────────  │
│  • 定时快照                         • 记录每个写命令         │
│  • 紧凑二进制格式                    • 可配置 fsync 策略      │
│  • 恢复速度快                        • 数据完整性高          │
│  • 可能丢失数据                      • 文件较大              │
│  • 适合备份                          • 适合实时恢复          │
│                                                             │
│  混合持久化 (Redis 4.0+): RDB 增量 + AOF 末尾               │
└─────────────────────────────────────────────────────────────┘
```

---

## 1. RDB 持久化

### 1.1 RDB 文件格式

**文件结构**：

```
+----------+----------+----------+----------+----------+
|  "REDIS" |  version |  DB 0    |  DB 1    |   EOF    |
|   (5B)   |  (4B)    |  (var)   |  (var)   |  (1B)    |
+----------+----------+----------+----------+----------+

每个 DB 内部:
+-------------+-------------+-------------+-------------+
|  SELECTDB   |  EXPIRETIME |    KEY      |   VALUE     |
|  (1+var)    |  (1+var)    |  (var)      |   (var)     |
+-------------+-------------+-------------+-------------+
```

**文件头**：

```c
/* RDB 版本 */
#define RDB_VERSION 12

/* 文件头格式：REDIS + 4 位版本字符 */
char magic[] = "REDIS";
char version[4];  // 如 "0012" 表示版本 12
```

**特殊 Opcodes**：

```c
/* RDB 特殊操作码 */
#define RDB_OPCODE_SLOT_INFO      244   /* 槽位信息 (集群模式) */
#define RDB_OPCODE_FUNCTION2      245   /* 函数库数据 */
#define RDB_OPCODE_MODULE_AUX     247   /* 模块辅助数据 */
#define RDB_OPCODE_IDLE           248   /* LRU 空闲时间 */
#define RDB_OPCODE_FREQ           249   /* LFU 频率 */
#define RDB_OPCODE_AUX            250   /* 辅助字段 */
#define RDB_OPCODE_RESIZEDB       251   /* 哈希表大小提示 */
#define RDB_OPCODE_EXPIRETIME_MS  252   /* 毫秒级过期时间 */
#define RDB_OPCODE_EXPIRETIME     253   /* 秒级过期时间 (旧) */
#define RDB_OPCODE_SELECTDB       254   /* 数据库选择 */
#define RDB_OPCODE_EOF            255   /* 文件结束 */
```

### 1.2 数据编码格式

**长度编码**：

```
第一字节的前两位决定编码方式:

00|XXXXXX  -> 6 位长度 (0-63)
01|XXXXXX XXXXXXXX -> 14 位长度 (0-16383)
10|000000 [32-bit] -> 32 位长度
10|000001 [64-bit] -> 64 位长度
11|XXXXXX -> 特殊编码

特殊编码类型:
#define RDB_ENC_INT8   0   /* 8 位有符号整数 */
#define RDB_ENC_INT16  1   /* 16 位有符号整数 */
#define RDB_ENC_INT32  2   /* 32 位有符号整数 */
#define RDB_ENC_LZF    3   /* LZF 压缩字符串 */
```

**对象类型映射**：

```c
/* RDB 类型定义 (固定，不能修改) */
#define RDB_TYPE_STRING         0
#define RDB_TYPE_LIST           1
#define RDB_TYPE_SET            2
#define RDB_TYPE_ZSET           3
#define RDB_TYPE_HASH           4
#define RDB_TYPE_ZSET_2         5   /* 二进制存储 double */
#define RDB_TYPE_MODULE_2       7   /* 模块类型 */
#define RDB_TYPE_LIST_QUICKLIST 14  /* quicklist 编码列表 */
#define RDB_TYPE_STREAM_LISTPACKS 15 /* stream 类型 */
#define RDB_TYPE_HASH_LISTPACK  16  /* listpack 编码哈希 */
/* ... 更多类型见 rdb.h */
```

### 1.3 保存触发机制

**手动触发**：

```bash
# 阻塞保存
SAVE

# 后台保存
BGSAVE

# 保存到指定文件
BGSAVE /path/to/file.rdb
```

**自动触发配置**：

```conf
# 满足任一条件即触发保存
save 900 1      # 900 秒内至少 1 个键变化
save 300 10     # 300 秒内至少 10 个键变化
save 60 10000   # 60 秒内至少 10000 个键变化
```

**内部触发**：

```c
/* serverCron() 中检查保存条件 */
void serverCron(void) {
    /* 检查 RDB 保存条件 */
    for (j = 0; j < server.saveparamslen; j++) {
        if (server.savedata[j].changes > server.saveparams[j].changes &&
            server.unixtime - server.lastsave > server.saveparams[j].seconds)
        {
            /* 触发 BGSAVE */
            rdbSaveBackground(RDB_CHILD_TYPE_DISK, tmpfile);
        }
    }
}
```

### 1.4 后台保存流程

```
主进程                              子进程
  |                                   |
  |--- fork() ----------------------> |
  |                                   |
  |<-- 返回子进程 PID ---------------- |
  |                                   |
  |        [写时复制 CoW]             |
  |                                   | 保存 RDB
  |                                   |
  |<-- 子进程退出 (SIGCHLD) ---------- |
  |                                   |
  | 更新状态，更新 lastsave           |
  |                                   |
```

**保存状态**：

```c
/* RDB 保存状态 */
struct redisServer {
    pid_t rdb_child_pid;              /* 保存子进程 PID */
    int rdb_child_type;               /* 保存类型 (DISK/SOCKET) */
    int rdb_save_time_last;           /* 上次保存开始时间 */
    int rdb_save_time_started;        /* 本次保存开始时间 */
    time_t lastsave;                  /* 上次成功保存时间 */
};
```

### 1.5 RDB 保存 API

```c
/* 核心保存函数 */
int rdbSaveToFile(const char *filename);           /* 保存到文件 */
int rdbSaveBackground(int req, char *filename,     /* 后台保存 */
                      rdbSaveInfo *rsi, int rdbflags);
int rdbSaveToSlavesSockets(int req, rdbSaveInfo *rsi); /* 发送给从节点 */

/* Rio 对象操作 */
ssize_t rdbSaveObject(rio *rdb, robj *o, robj *key, int dbid);
ssize_t rdbSaveStringObject(rio *rdb, robj *obj);
int rdbSaveType(rio *rdb, unsigned char type);
int rdbSaveLen(rio *rdb, uint64_t len);

/* 加载函数 */
int rdbLoad(char *filename, rdbSaveInfo *rsi, int rdbflags);
robj *rdbLoadObject(int rdbtype, rio *rdb, sds key, int dbid, int *error);
```

### 1.6 RDB 优缺点

**优点**：
- 文件紧凑，适合备份
- 恢复速度快
- 支持版本兼容

**缺点**：
- 可能丢失大量数据
- 保存大量数据时可能阻塞
- 大文件 fork 耗时

## 2. AOF 持久化

### 2.1 AOF 文件结构

**文件格式**：

```
*2\r\n$6\r\nSELECT\r\n$1\r\n0\r\n        # SELECT 0
*3\r\n$3\r\nSET\r\n$3\r\nfoo\r\n$3\r\nbar\r\n  # SET foo bar
*2\r\n$4\r\nINCR\r\n$7\r\ncounter\r\n  # INCR counter
...
```

**AOF 清单文件 (Manifest)**:

```
# Redis AOF manifest file
file appendonly.aof.2.base.rdb seq 2 type b
file appendonly.aof.1.incr.aof seq 1 type h
file appendonly.aof.2.incr.aof seq 2 type h
file appendonly.aof.3.incr.aof seq 3 type h
file appendonly.aof.4.incr.aof seq 4 type i
file appendonly.aof.5.incr.aof seq 5 type i
```

**文件类型**：
- `type b` - BASE: RDB 快照
- `type i` - INCR: 当前增量 AOF
- `type h` - HISTORY: 历史文件

### 2.2 AOF 数据结构

```c
/* AOF 信息结构 */
typedef struct aofInfo {
    sds file_name;              /* 文件名 */
    uint64_t file_seq;          /* 文件序列号 */
    int file_type;              /* 文件类型 (BASE/INCR/HISTORY) */
    long long start_offset;     /* 起始偏移量 */
    long long end_offset;       /* 结束偏移量 */
} aofInfo;

/* AOF 清单 */
typedef struct aofManifest {
    aofInfo *base_aof_info;              /* BASE 文件信息 */
    list *incr_aof_list;                 /* INCR 文件列表 */
    list *history_aof_list;              /* HISTORY 文件列表 */
    sds manifest_content;                /* 清单内容 */
    int dirty;                           /* 是否需要重写清单 */
} aofManifest;
```

### 2.3 命令追加流程

```c
/* 将命令追加到 AOF 缓冲区 */
void feedAppendOnlyFile(client *c) {
    /* 1. 构建 RESP 协议 */
    robj **argv = c->argv;
    int argc = c->argc;

    /* 2. 写入 AOF 缓冲区 */
    sds apobuf = catAppendOnlyGenericCommand(apobuf, argc, argv);

    /* 3. 写入 AOF 文件 */
    if (sdslen(apobuf) > 0) {
        if (write(server.aof_fd, apobuf, sdslen(apobuf)) == -1) {
            /* 处理写入错误 */
        }
    }
}
```

**调用点**：

```c
/* 在 call() 函数中传播命令 */
void call(client *c, int flags) {
    /* ... 执行命令 ... */

    /* 传播到 AOF */
    if (server.aof_state != AOF_OFF && !(flags & CMD_CALL_PROPAGATE_AOF))
        propagatePendingCommand(c);

    /* 传播到复制流 */
    if (server.masterhost == NULL && !(flags & CMD_CALL_PROPAGATE_REPL))
        propagatePendingCommand(c);
}
```

### 2.4 Fsync 策略

```conf
# AOF 同步策略
appendfsync always    # 每次写入都 fsync (最安全，最慢)
appendfsync everysec  # 每秒 fsync 一次 (推荐)
appendfsync no        # 由 OS 决定何时同步 (最快，可能丢失数据)
```

**实现逻辑**：

```c
void flushAppendOnlyFile(int force) {
    /* 写入文件 */
    nwritten = write(server.aof_fd, server.aof_buf, sdslen(server.aof_buf));

    /* 根据策略 fsync */
    if (server.aof_fsync == AOF_FSYNC_ALWAYS) {
        aof_fsync(server.aof_fd);
    } else if (server.aof_fsync == AOF_FSYNC_EVERYSEC &&
               server.unixtime > server.aof_last_fsync_time)
    {
        /* 异步 fsync */
        bioCreateFsyncJob(server.aof_fd);
    }
}
```

### 2.5 AOF 重写机制

**为什么需要重写**：

```
原始 AOF:
SET foo bar
SET foo hello
INCR counter
INCR counter
SET counter 100

重写后:
SET foo hello
SET counter 100
```

**重写流程**：

```
主进程                              子进程
  |                                   |
  |--- fork() ----------------------> |
  |                                   |
  |  继续处理命令                     | 读取当前数据快照
  |  写入 AOF 缓冲区                   | 生成重写 AOF
  |                                   |
  |  累积差异命令                     | 写入完成，发送信号
  |                                   |
  |<-- 子进程退出 -------------------- |
  |                                   |
  |  追加差异命令到新 AOF             |
  |  原子替换旧 AOF                   |
  |                                   |
```

**重写触发**：

```conf
# AOF 重写触发条件
auto-aof-rewrite-percentage 100   # 增长 100% 时触发
auto-aof-rewrite-min-size 64mb    # 最小 64MB
```

```c
/* 检查是否需要重写 */
int shouldRewriteAppendOnlyFile(void) {
    if (server.aof_rewrite_scheduled) return 1;

    if (server.aof_current_size > server.aof_rewrite_min_size &&
        server.aof_current_size > server.aof_rewrite_base_size * 2)
    {
        return 1;
    }
    return 0;
}
```

### 2.6 混合持久化 (Redis 4.0+)

**原理**：
- AOF 文件前缀为 RDB 格式快照
- 后续追加增量命令

**配置**：

```conf
aof-use-rdb-preamble yes    # 启用混合持久化
```

**文件格式**：

```
+------------------+------------------+
|   RDB 快照部分   |   AOF 增量部分   |
|   (二进制)       |   (RESP 协议)     |
+------------------+------------------+
```

**优势**：
- 结合 RDB 和 AOF 的优点
- 快速加载 + 数据完整
- 重写更快

## 3. 数据恢复策略

### 3.1 启动加载顺序

```
1. 检查 AOF 是否启用
   ├─ 是：加载 AOF (最快路径)
   └─ 否：检查 RDB

2. 检查 RDB 文件
   ├─ 存在：加载 RDB
   └─ 不存在：空数据库启动
```

### 3.2 AOF 加载流程

```c
int loadAppendOnlyFile(char *filename) {
    /* 1. 加载清单文件 */
    aofManifest *am = loadAofManifest();

    /* 2. 按顺序加载 BASE + INCR 文件 */
    if (am->base_aof_info) {
        loadAofFile(am->base_aof_info->file_name);
    }

    listIter li;
    listNode *ln;
    listRewind(am->incr_aof_list, &li);
    while((ln = listNext(&li))) {
        aofInfo *ai = ln->value;
        loadAofFile(ai->file_name);
    }

    return C_OK;
}
```

### 3.3 加载选项

```c
/* 加载标志 */
#define RDBFLAGS_NONE 0
#define RDBFLAGS_AOF_PREAMBLE (1<<0)    /* RDB 作为 AOF 前缀 */
#define RDBFLAGS_REPLICATION (1<<1)     /* 复制场景加载 */
#define RDBFLAGS_ALLOW_DUP (1<<2)       /* 允许重复键 */
```

## 5. 持久化方案对比

| 特性 | RDB | AOF | 混合持久化 |
|------|-----|-----|------------|
| 数据完整性 | 低 | 高 | 高 |
| 恢复速度 | 快 | 慢 | 快 |
| 文件大小 | 小 | 大 | 中 |
| 性能影响 | 中 (fork) | 高 (fsync) | 中 |
| 适合场景 | 备份/灾备 | 实时恢复 | 通用 |

**推荐配置**：

```conf
# 生产环境推荐
appendonly yes
aof-use-rdb-preamble yes
appendfsync everysec
save 900 1
rdbcompression yes
rdbchecksum yes
```
