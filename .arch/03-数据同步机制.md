# 数据同步机制

Redis 的数据同步机制是实现高可用和分布式部署的核心。本章详细描述主从复制、部分重同步、RDB 通道等机制。

## 同步机制总览

```
主从复制架构:

                        +-------------+
                        |   Master    |
                        |             |
                        |  repl_backlog |
                        |   (缓冲区)   |
                        +------+------+
                               |
         +---------------------+---------------------+
         |                     |                     |
         v                     v                     v
  +------+------+       +------+------+       +------+------+
  |  Replica 1  |       |  Replica 2  |       |  Replica 3  |
  +-------------+       +-------------+       +-------------+

同步类型:
├── 全量同步 (Full Synchronization)
│   ├── 基于 RDB 的快照传输
│   └── 无磁盘复制 (Diskless Replication)
│
└── 部分同步 (Partial Synchronization)
    ├── 基于复制积压缓冲区
    └── PSYNC 命令
```

---

## 1. 复制基础架构

### 1.1 复制积压缓冲区 (Replication Backlog)

**作用**：
- 缓存最近的写命令
- 支持部分重同步
- 减少全量同步频率

**数据结构**：

```c
/* 复制积压缓冲区结构 */
typedef struct replBacklog {
    /* 缓冲区引用节点 */
    listNode *ref_repl_buf_node;

    /* 未索引的块数量 */
    unsigned long unindexed_count;

    /* 块索引 (rax 树，用于快速查找偏移量) */
    rax *blocks_index;

    /* 历史长度 (缓冲区中有效数据量) */
    long long histlen;

    /* 缓冲区起始偏移量 */
    long long offset;
} replBacklog;

/* 复制缓冲区块 */
typedef struct replBufBlock {
    int refcount;           // 引用计数
    size_t size;            // 块大小
    size_t used;            // 已使用大小
    long long repl_offset;  // 复制偏移量
    unsigned long id;       // 块 ID
    char buf[];             // 数据缓冲区
} replBufBlock;
```

**内存布局**：

```
server.repl_buffer_blocks (全局复制缓冲区链表):
  +------+------+------+------+
  | blk1 | blk2 | blk3 | ...  |
  +------+------+------+------+
     |      |      |
     v      v      v
  +------+------+------+
  | blk1 | blk2 | blk3 |  ← replication backlog 引用
  +------+------+------+

每个块结构:
  +----------+----------+--------+--------+--------+
  | refcount |  size    |  used  | offset |  buf   |
  |    2     |  16384   |  8192  | 100000 |  ...   |
  +----------+----------+--------+--------+--------+
```

**关键参数**：

```c
// 配置参数
repl-backlog-size 1MB        // 积压缓冲区大小
repl-backlog-ttl 3600        // 从节点断开后保留时间

// 内部常量
#define REPL_BACKLOG_INDEX_PER_BLOCKS 64  // 每 64 块创建一个索引
#define REPL_BACKLOG_TRIM_BLOCKS_PER_CALL 1  // 每次修剪的块数
```

### 1.2 复制 ID (Replication ID)

Redis 使用两个复制 ID 来标识主节点状态：

```c
struct redisServer {
    char replid[CONFIG_RUN_ID_SIZE+1];   // 当前复制 ID
    char replid2[CONFIG_RUN_ID_SIZE+1];  // 上一个复制 ID
    long long master_repl_offset;        // 主节点复制偏移量
    long long second_replid_offset;      // 切换到 replid2 时的偏移量
};
```

**复制 ID 切换时机**：
1. 主节点重启
2. 从节点晋升为主节点
3. 创建新的复制积压缓冲区

## 2. 全量同步 (Full Synchronization)

### 2.1 全量同步流程

```
从节点视角:
1. 发送 PSYNC 命令
2. 等待 RDB 快照
3. 接收 RDB 数据
4. 加载 RDB
5. 接收缓冲区命令
6. 进入增量同步

主节点视角:
1. 接收 PSYNC 请求
2. 判断是否可部分同步
3. 如需全量：启动 BGSAVE
4. 发送 RDB 给从节点
5. 继续发送缓冲区命令
6. 进入正常复制状态
```

**时序图**：

```
Slave                               Master
  |                                   |
  |-------- PSYNC ? -1 -------------> |
  |                                   |
  |<------ FULLRESYNC <id> 0 -------- |  (需要全量同步)
  |                                   |
  |         [BGSAVE 启动]              |
  |                                   |
  |<====== RDB 数据传输 ============> |
  |                                   |
  |         [RDB 加载]                 |
  |                                   |
  |<--- 复制缓冲区命令 --------------> |
  |                                   |
  |======== 正常复制命令 ============> |
  |                                   |
```

### 2.2 全量同步触发条件

1. **初次复制**：从节点首次连接主节点
2. **复制 ID 不匹配**：从节点保存的 replication ID 无效
3. **偏移量过期**：请求的偏移量不在 backlog 中
4. **主节点切换**：主节点发生变化

```c
/* 判断是否需要全量同步 */
if (slave->replid[0] == '\0') {
    /* 从节点没有保存 replication ID，需要全量同步 */
    need_full_resync = 1;
} else if (memcmp(slave->replid, server.replid, CONFIG_RUN_ID_SIZE) != 0) {
    /* replication ID 不匹配，尝试检查 replid2 */
    if (memcmp(slave->replid, server.replid2, CONFIG_RUN_ID_SIZE) != 0) {
        need_full_resync = 1;
    }
}

/* 检查偏移量是否在 backlog 范围内 */
if (slave->repl_off < server.repl_backlog->offset) {
    /* 偏移量太小，已过期 */
    need_full_resync = 1;
}
```

### 2.3 RDB 传输方式

#### 传统方式（基于磁盘）

```c
// 1. 主节点保存 RDB 到临时文件
rdbSaveBackground(RDB_CHILD_TYPE_DISK, tmpfile);

// 2. 子进程写入磁盘
// 3. 主进程读取文件发送给从节点
fd = open(tmpfile, O_RDONLY);
sendfile(slave->conn->fd, fd, NULL, filesize);

// 4. 删除临时文件
unlink(tmpfile);
```

#### 无磁盘复制（Diskless Replication）

```c
// 直接通过 socket 传输，不经过磁盘
if (server.repl_diskless_sync) {
    // 创建 RDB 并通过 socket 直接发送
    rdbSaveBackground(RDB_CHILD_TYPE_SOCKET, slave->conn->fd);
}
```

**配置选项**：

```conf
# 无磁盘复制模式
# disabled - 使用磁盘
# swapdb   - 使用 swap 数据库
# diskless - 纯无磁盘
repl-diskless-sync disabled

# 延迟发送 RDB 时间 (等待更多从节点连接)
repl-diskless-sync-delay 5
```

### 2.4 RDB Channel 机制（高级复制）

**问题背景**：
- 传统方式中，RDB 传输期间主节点需要缓存所有写命令
- 对于大 RDB 文件，可能导致内存峰值

**解决方案**：
- 使用独立的 RDB Channel 传输快照
- 主 Channel 继续传输命令
- 从节点并行接收 RDB 和命令

```c
/* RDB Channel 复制状态 */
#define REPL_STATE_WAIT_RDB_CHANNEL  4  /* 等待 RDB Channel 建立 */
#define REPL_STATE_RDB_CHANNEL_TRANSFER 5 /* RDB Channel 传输中 */

/* RDB Channel 处理流程 */
static void rdbChannelFullSyncWithMaster(connection *conn) {
    // 1. 建立 RDB Channel 连接
    // 2. 通过 RDB Channel 接收 RDB 数据
    // 3. 同时通过主 Channel 接收命令
    // 4. 异步加载 RDB 数据
}
```

## 3. 部分同步 (Partial Synchronization)

### 3.1 PSYNC 命令

```
语法：
PSYNC <replicationid> <offset>

参数:
- replicationid: 从节点保存的复制 ID
- offset: 从节点已处理的偏移量

响应:
- FULLRESYNC <replid> <offset>  - 需要全量同步
- CONTINUE                     - 可以继续增量同步
- TRYAGAIN                     - 稍后重试
```

### 3.2 部分同步流程

```
Slave                               Master
  |                                   |
  |--- PSYNC <id> 100000 ----------> |
  |                                   |
  |  [检查: id 匹配 && offset 有效]     |
  |                                   |
  |<------- CONTINUE ---------------> |  (可以继续)
  |                                   |
  |<=== 从 offset=100001 开始发送 ===> |
  |                                   |
```

### 3.3 部分同步条件

```c
/* 判断是否可以进行部分重同步 */
int canPartialResync(client *slave) {
    /* 1. 复制 ID 必须匹配 (replid 或 replid2) */
    if (memcmp(slave->replid, server.replid, CONFIG_RUN_ID_SIZE) != 0 &&
        memcmp(slave->replid, server.replid2, CONFIG_RUN_ID_SIZE) != 0) {
        return C_ERR;
    }

    /* 2. 偏移量必须在 backlog 范围内 */
    if (slave->repl_off < server.repl_backlog->offset) {
        return C_ERR;  /* 偏移量太小 */
    }
    if (slave->repl_off > server.master_repl_offset) {
        return C_ERR;  /* 偏移量太大 */
    }

    /* 3. backlog 中必须有该偏移量的数据 */
    if (!findReplicationBacklogBlock(slave->repl_off)) {
        return C_ERR;
    }

    return C_OK;
}
```

### 3.4 偏移量查找优化

**rax 索引结构**：

```
blocks_index (rax 树):
                    +--------+
                    | root   |
                    +--------+
                   /          \
          +--------+          +--------+
          |offset:0|          |offset: |
          | node   |----------| 65536  |
          +--------+          +--------+
                                  |
                             +--------+
                             |offset: |
                             | 131072 |
                             +--------+

查找过程: O(log N)
1. 在 rax 树中查找 >= 请求偏移量的最小索引
2. 从该索引对应的链表节点开始遍历
3. 计算块内位置
```

```c
/* 在复制缓冲区中查找偏移量位置 */
int findReplicationBacklogBlock(long long offset) {
    /* 在 rax 索引中查找 */
    uint64_t encoded_offset = htonu64(offset);
    raxIterator ri;
    raxStart(&ri, server.repl_backlog->blocks_index);
    raxSeek(&ri, ">=", (unsigned char*)&encoded_offset, sizeof(uint64_t));

    if (raxEOF(&ri)) {
        /* 偏移量超出范围 */
        return C_ERR;
    }

    /* 获取链表节点 */
    listNode *ln = raxGetData(&ri);
    replBufBlock *block = listNodeValue(ln);

    /* 计算块内位置 */
    long long pos = offset - block->repl_offset;

    return C_OK;
}
```

## 4. 复制状态机

### 4.1 主节点状态

```c
/* 主节点不需要特殊状态，但需要维护从节点信息 */

/* 从节点在主节点的状态 */
typedef struct client {
    int replstate;       /* 复制状态 */
    long long reploff;   /* 已确认的偏移量 */
    long long repl_ack_off;  /* ACK 偏移量 */
    time_t repl_ack_time;    /* 最后 ACK 时间 */
} client;
```

### 4.2 从节点状态

```c
/* 从节点复制状态 */
#define REPL_STATE_NONE              0  /* 未复制 */
#define REPL_STATE_CONNECT         1    /* 正在连接 */
#define REPL_STATE_CONNECTING      2    /* 连接中 */
#define REPL_STATE_TRANSFER        3    /* 传输中 */
#define REPL_STATE_CONNECTED       4    /* 已连接 */
#define REPL_STATE_WAIT_BGSAVE_START 5  /* 等待 BGSAVE 开始 */
#define REPL_STATE_WAIT_BGSAVE_END   6  /* 等待 BGSAVE 结束 */
#define REPL_STATE_WAIT_RDB_CHANNEL  7  /* 等待 RDB Channel */
```

**状态转换图**：

```
                    +-------------+
                    | REPL_STATE_NONE |
                    +--------+------+
                             |
                             | sync 命令
                             v
                    +--------+------+
                    | REPL_STATE_CONNECT |
                    +--------+------+
                             |
                             | 连接成功
                             v
                    +--------+------+
                    | REPL_STATE_CONNECTING |
                    +--------+------+
                             |
                             | 发送 PSYNC
                             v
                    +--------+------+      需要全量
                    | REPL_STATE_WAIT_BGSAVE_START |
                    +--------+------+
                             |
                             | BGSAVE 完成
                             v
                    +--------+------+
                    | REPL_STATE_TRANSFER |
                    +--------+------+
                             |
                             | RDB 加载完成
                             v
                    +--------+------+
                    | REPL_STATE_CONNECTED |
                    +-------------+
```

## 5. 心跳与故障检测

### 5.1 心跳机制

```c
/* 主节点定期发送 PING 给从节点 */
void replicationCron(void) {
    /* 发送 ACK 到主节点 (从节点视角) */
    if (server.masterhost &&
        server.repl_state == REPL_STATE_CONNECTED)
    {
        robj *argv[3];
        argv[0] = createStringObject("REPLCONF",8);
        argv[1] = createStringObject("ACK",3);
        argv[2] = createStringObjectFromLongLong(server.master_repl_offset);
        // 发送...
    }

    /* 检测从节点超时 (主节点视角) */
    listIter li;
    listNode *ln;
    listRewind(server.slaves, &li);
    while((ln = listNext(&li))) {
        client *slave = ln->value;
        if (server.master_repl_offset - slave->repl_ack_off >
            server.repl_timeout * 1024 * 1024) {
            /* 从节点超时 */
            freeClient(slave);
        }
    }
}
```

### 5.2 超时配置

```conf
# 从节点超时时间 (秒)
repl-timeout 60

# PING 间隔 (秒)
repl-ping-replica-period 10
```

## 6. 关键数据结构总结

```c
/* 服务器中的复制相关字段 */
struct redisServer {
    /* 主节点配置 */
    char *replid;                  /* 当前复制 ID */
    char *replid2;                 /* 上一个复制 ID */
    long long master_repl_offset;  /* 主节点复制偏移量 */
    long long second_replid_offset;/* replid2 起始偏移量 */

    replBacklog *repl_backlog;     /* 复制积压缓冲区 */

    /* 从节点列表 */
    list *slaves;                  /* 从节点客户端列表 */

    /* 全局复制缓冲区 */
    list *repl_buffer_blocks;      /* 复制缓冲区块链表 */
    size_t repl_buffer_mem;        /* 复制缓冲区内存使用 */

    /* 作为从节点的配置 */
    char *masterhost;              /* 主节点地址 */
    int masterport;                /* 主节点端口 */
    struct client *master;         /* 主节点客户端 */
    int repl_state;                /* 复制状态 */
};

/* 客户端中的复制相关字段 */
typedef struct client {
    /* 从节点特有字段 */
    int replstate;                 /* 复制状态 */
    long long reploff;             /* 已发送偏移量 */
    long long repl_ack_off;        /* 已确认偏移量 */
    time_t repl_ack_time;          /* 最后 ACK 时间 */

    /* 复制缓冲区引用 */
    listNode *ref_repl_buf_node;   /* 引用的第一个缓冲区块 */
    size_t ref_block_pos;          /* 块内位置 */
} client;
```

```conf

# ======================== 其他 ========================
```
